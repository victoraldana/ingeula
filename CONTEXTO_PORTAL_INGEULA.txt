1. VISION Y OBJETIVO DEL PROYECTO
--------------------------------------------------------------------------------

- Institucion: Facultad de Ingenieria de la Universidad de Los Andes (ULA),

  jerarquia visual (azul institucional profundo, blanco puro, grises suaves,
  mega-menu de navegacion, hero fotografico de alto impacto, tarjetas modulares
  y bloques editoriales de noticias/comunidad).
- Alcance inicial (Fase 1 - completada):
  * Inicializar repositorio Git en D:\ingeula (rama principal: main).
  * Crear la landing page institucional con informacion general de la Facultad
    de Ingenieria ULA.
  * Dejar lista la arquitectura y rutas base para las 5 escuelas principales de
    ingenieria solicitadas:
      1. Ingenieria de Sistemas   (/escuelas/sistemas)
      2. Ingenieria Electrica     (/escuelas/electrica)

2. STACK TECNOLOGICO Y ENTORNO
--------------------------------------------------------------------------------
- Framework: Next.js 15 (App Router) + React 19
- Lenguaje: TypeScript (strict: true)
- Estilos: Tailwind CSS v4 (@tailwindcss/postcss)
- Iconografia: lucide-react
- Imagenes: assets estaticos locales en /public/images (next.config.ts usa
  `images: { unoptimized: true }` para facilitar despliegues estaticos o en
  cualquier hosting).
- Entorno local verificado:
  * SO: Windows
  * Ruta workspace: D:\ingeula
  * Node.js: v22.19.0 | npm: 11.14.1 | Git: 2.51.0
  * Nota: `gh` CLI no estaba instalado; el repo es local en rama `main` y aun
    no tiene remoto (`origin`) configurado en GitHub.

  `src/data/faculty.ts`) con autoplay, pausa/reanudacion, flechas, tabs
  numerados y transicion suave para destacar anuncios/informacion apenas entra
  el visitante, mas barra inferior de acceso directo a las 5 escuelas.

6. GUIA PARA FUTUROS AGENTES AL EXTENDER EL PORTAL
--------------------------------------------------------------------------------
1. Para editar o ampliar informacion de una escuela:
   - Revisar primero `src/data/schools.ts` (tipo `EngineeringSchool`).
   - Si cada escuela crece con subpaginas propias (ej. `/escuelas/sistemas/pensum`,
     `/escuelas/sistemas/laboratorios`, `/escuelas/sistemas/noticias`), se pueden
     crear subcarpetas bajo `src/app/escuelas/[slug]/` o separar datos por archivo
     en `src/data/schools/<slug>.ts`.
2. Para agregar noticias, eventos o informacion institucional:
   - Editar `src/data/faculty.ts` o migrar a MDX / CMS headless cuando el
     volumen de publicaciones crezca.
3. Coherencia visual:
   - Mantener el estilo sobrio, academico y moderno tipo `tec.mx/es`.
   - Respetar la paleta azul institucional (`#0039A6` / `#001A4D`) y evitar
     recargar la UI con colores o animaciones innecesarias.
   - Mantener soporte 100% responsivo (mobile-first) y contenido en espanol.
4. Verificacion obligatoria antes de entregar cambios:
   - Ejecutar `npm run build` para validar TypeScript, Tailwind y generacion SSG.
   - Hacer commits claros y atomicos en la rama `main` (o rama de feature si el
     usuario lo solicita).
